# ADR 0003 - PDF ingestion and derived-evidence provenance

Status: accepted (2026-09-06)

## Context

Every real investment policy arrives as a PDF. Until now the pipeline took a string, which
meant the highest-risk transformation in the whole system - turning a client's signed
document into the character stream every span offset refers to - was happening off-stage,
undocumented and untested.

Three failure modes drove the design.

**Silent match defeat.** A justified PDF renders "delivery versus payment" as
"delivery ver-\\nsus payment". The anti-pattern misses, the control scores CONFORMING, and
the deficiency never appears in the report. The same applies to ligatures, smart quotes
and non-breaking spaces. Every one of these turns a finding into a non-finding without
raising an error.

**Confident nonsense on unreadable input.** A scanned, image-only PDF extracts as
near-empty text. Every control resolves ABSENT and the pipeline emits a 0.00 statutory
index for a policy nobody has read. That output is worse than no output, because it looks
like a finding rather than a malfunction.

**Unprovable evidence.** A span at offset 41892 means nothing to a board. A page number
does.

## Decision

Ingestion is a first-class stage with its own provenance record.

- **Backends are pluggable and reported**, mirroring the adapter pattern: `pdftotext`
  (preferred, `-layout` so table figures stay with their fund), `pypdf` (used only if
  already installed), and a zero-dependency stdlib extractor that always runs. The project
  keeps zero runtime dependencies.
- **Normalization is shared across backends** so swapping one cannot quietly change how
  text is cleaned, and every transform is counted into the ledger.
- **Dehyphenation is conservative**: a line-ending hyphen joins only when the next line
  begins lowercase, so "dollar-weighted" survives and "ver-\\nsus" does not.
- **A quality gate refuses what it cannot read.** UNUSABLE raises rather than returning,
  and `force=True` is the only way past it.
- **Provenance travels with the text**: source hash, derived-text hash, backend, page
  count, transform counts and warnings, all recorded in the ledger.
- **Every span resolves to a page.** Offsets stay, because they are what verification
  proved; the page is the human-facing projection.

## Consequences

- The ledger now distinguishes the document the client signed from the text the review
  actually ran against, and names every difference between them.
- A golden case pins the same policy as text and as PDF; they must produce identical
  verdicts, so ingestion regressions surface as a diff rather than as a slightly different
  score nobody questions.
- PDF fixtures are generated by a stdlib script and regenerated in CI, so the repository
  contains no binary artifact it cannot rebuild.
- Golden cases pin their backend explicitly. An expectation that depends on whether
  poppler is installed on the runner is not an expectation.

## Revisit when

A client policy arrives as a scanned document often enough that refusing it is the wrong
answer. At that point OCR becomes a fourth backend, and its output should be marked
DEGRADED by default rather than trusted at the same level as extracted text.
